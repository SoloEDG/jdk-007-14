# 夜航音乐工作室

安装：`npm install`

本地启动：`npm run dev`，访问终端显示的地址。

Docker 启动：`docker compose up --build -d`，访问 http://localhost:18027 。

## 条件化循环（概率 / 间隔 / 前置）

音符可携带一个可选的触发条件（`NoteCondition`），未携带条件的旧音符每圈必定触发。

- **出现概率 `probability`（0~1）**：由「可保存的种子 + 轨道/音符 ID + 圈序号」
  通过确定性哈希决定，纯函数、与抽取顺序无关。
- **每几圈触发 `every` + 起始相位 `phase`**：仅当 `圈序号 % every === phase` 时触发。
- **前置音符 `prerequisiteId`**：前置音符必须位于本音符之前，且在本圈先成功触发，
  本音符才会触发。前置缺失、指向自己、位于本音符之后或互相成环时，应用会被拒绝，
  原有可播放内容完整保留。

### 确定性与一致性

- 时间轴预览与音频调度调用同一个纯函数 `evaluateTrack(track, seed, loopIndex)`，
  不存在“预览抽一次、调度再抽一次”的两套随机数；调度器对 `(轨道, 种子, 圈)`
  的判定结果做缓存。
- **暂停再继续**：判定是无状态纯函数，已经过的步骤不会重新抽取。
- **从头重播（停止后再播放）**：圈序号归零，同一种子逐圈完整复现。
- 播放中修改条件或种子会进入暂存（pending），在跨圈边界统一落库后才影响新一圈，
  保证已预排的声音与时间轴高亮一致；停止会丢弃未生效的暂存。

### 录音的两种提交方式

- **烘焙固定（bake）**：把这一圈实际听到的音符写为确定音符，移除全部条件，
  存档中不再含 `condition`。
- **保留演化（evolve）**：新录的音符并入轨道，原有条件保留并继续逐圈演化，
  存档中保留 `condition`。
- 也可用轨道操作里的「烘焙第 N 圈」直接把指定预览圈固定下来。

### 存档格式

当前为 `version: 2`，在 v1 基础上新增顶层 `seed`（uint32）与音符级可选 `condition`。
读取 v1 存档时自动迁移：补默认种子 `1`，旧音符保持每圈必触发，行为不变。
